# 문명 보드게임 프로토타입

보드게임 규칙 검증용 프로토타입 (TypeScript, 핫시트). 규칙서 원문은 [`docs/rules.md`](docs/rules.md).

## 구조
- `src/engine/` — UI와 무관한 순수 규칙 엔진 (`createGame`, `apply(state, action)`).
  - `data/*.json` — 문명·지형·자원·자연경관·기술 트리(52장)·군사 카드 데이터 (나중에 Java 등으로 옮길 때 그대로 재사용)
  - `data/tiles.json` — **실제 타일 카드 160장** (카드 하단 인쇄 산출을 엔진 계산과 테스트로 대조). `placeholderDeck.ts`는 160장이 안 모였을 때의 대비용
- `src/engine/ai.ts` — 규칙 검증용 휴리스틱 AI (UI의 AI 자리, 시뮬레이션에 사용)
- `src/ui/` — React 핫시트 화면 (`GameScreen`, 단계별 `panels/`)

## 명령
```
npm install
npm test        # 규칙 테스트
npm run dev     # 개발 서버 (핫시트 화면)
npm run build:single   # 오프라인으로 열 수 있는 단일 HTML: dist-single/civ5.html
```

## 진행 상황
- [x] 1단계: 준비, 일꾼 배치, 산출, 식량 정산, 기술 연구
- [x] 2단계: 불가사의(투자·정산·완성 효과), 정책 8종, 두 번째 도시, 관광·고고학
- [x] 3단계: 군사 카드 생산·승급, 정찰·나침반, 선전포고, 전투, 도시 파괴, 원자폭탄, 승패 판정, 독일·중국·인도·스웨덴·몽골·일본·스페인·브라질 능력
- [x] 4단계: 문명 능력·고유 유닛, 승패 판정 (3단계와 함께 구현)
- [x] 5단계: 핫시트 UI(시작 화면, 가림막, 단계별 패널, 전투 화면, 되돌리기, 자동 저장), 휴리스틱 AI

규칙서에서 애매하거나 데이터가 빠진 부분은 [`docs/open-questions.md`](docs/open-questions.md)에 모아둠.

## 플레이 방법
1. 시작 화면에서 문명(2~6명)과 사람/AI를 고르고 시드를 정합니다. 같은 시드는 같은 타일 순서를 만듭니다.
2. 사람 자리가 둘 이상이면 차례가 바뀔 때 가림막이 나옵니다 (손에 든 타일, 군사 카드는 비공개).
3. 차례는 규칙서 순서입니다: 일꾼 배치 → 산출 → 기술 연구 → 생산 → 식량 정산 → 선전포고. 전투는 라운드 정산에서 진행됩니다.
4. 되돌리기로 직전 행동을 취소할 수 있고, 진행 상황은 브라우저에 자동 저장됩니다 (시작 화면의 이어하기).

## AI 시뮬레이션으로 확인한 것
AI끼리 40판(2~5명, 문명 조합 다양)을 돌려도 크래시와 불변식 위반(카드 보존, 타일 id 중복, 일꾼 ≤ 행복)이 없었습니다.
밸런스 관찰: 승패가 난 판은 모두 문화 승리였습니다. 문화(타일 수)는 천천히 늘고, 관광은 불가사의·정책으로 빠르게 늘기 때문입니다.
아폴로 프로젝트는 과학 20을 **한 차례에** 모아야 해서 AI가 도달하지 못했습니다.
